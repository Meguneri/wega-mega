# LLM-NPC «Ева» — компаньон на языковой модели

NPC, который слышит происходящее вокруг, думает через OpenAI-совместимый API и живёт в мире:
говорит, ходит, готовит настоящие коктейли, помнит людей. Прототип: `MobLlmCompanion`
(`Resources/Prototypes/_Wega/Entities/Mobs/NPCs/llm_companion.yml`) — спавнить за барной стойкой,
точка спавна становится её «своим местом».

## Архитектура (три слоя)

```
ГОЛОВА  LlmNpcSystem.cs      — слух (речь+эмоуты), осмотр, промпт, вызов API, исполнение ответа
ДЕЙСТВИЯ LlmNpcSystem.Actions — инструменты (tool-calling): web_search, make_drink, go_to,
                                give_item, pick_up, follow, walk, stop, be_quiet, slap, attack,
                                set_mood, set_attitude, fight_stats; запасы бара
ТЕЛО    LlmNpcSystem.Body     — поручения (стиринг/pathfinding), взгляд, блуждание, вручение
        LlmBackend            — HTTP к chat-completions: tool-loop, JSON-режим, ретраи, gpt-5/o*
        LlmNpcMemory          — файл памяти data/llm_npc/<name>.md + автоконсолидация
        LlmDrinks             — каталог реальных коктейлей из ReactionPrototype (группа Drinks)
        LlmSearch             — веб-поиск (DuckDuckGo Instant Answers, бесключевой)
```

Ответ модели — строго JSON `{say, emote, remember}` (форсируется `response_format: json_object`;
не-JSON фолбэком уходит в say, чтобы NPC никогда не молчал после действий).

## CVar'ы (`[wega]` в server_config.toml)

| cvar | default | смысл |
|---|---|---|
| `llm_npc_enabled` | false | мастер-выключатель |
| `llm_npc_api_key` | "" | ключ (SERVERONLY+CONFIDENTIAL; только в untracked toml!) |
| `llm_npc_endpoint` | openrouter.ai/... | любой OpenAI-совместимый chat-completions |
| `llm_npc_model` | anthropic/claude-haiku-4.5 | id модели у провайдера |
| `llm_npc_reply_delay` | 2.5 | секунд тишины перед ответом |
| `llm_npc_web_search` | false | инструмент web_search |
| `llm_npc_make_drinks` | true | каталог напитков + make_drink |
| `llm_npc_api_key2` | "" | второй ключ — для NPC с `apiKeyCvar: "wega.llm_npc_api_key2"` в прототипе |
| `llm_npc_prices` | см. дефолт | прайс: `модель=вход/выход[/кэш];...` ($ за 1М токенов) |
| `llm_npc_budget_usd` | 0 | долларовый потолок расходов за раунд (0 = без лимита) |

## Расход API и лимиты

- **Точные токены** берутся из `usage`-блока каждого ответа провайдера (включая
  `prompt_tokens_details.cached_tokens` — кэшированный промпт биллится дешевле; наш промпт в
  основном статичный, кэш-скидка существенная). Стоимость считается по `llm_npc_prices`;
  модель вне прайса — токены точные, стоимость «?». Счётчик группируется по «NPC | хвост
  ключа | модель» и сбрасывается на рестарте раунда (`LlmNpcUsage`).
- **Посмотреть**: админ-команда **`llmnpc_usage`** (консоль сервера или админ-консоль клиента) —
  две секции: за раунд и «общий срез за всё время» (копится между раундами и рестартами:
  сохраняется в `data/llm_npc/usage.json` — раз в минуту при изменениях и на рестарте раунда;
  обнулить срез = удалить файл при выключенном сервере). Плюс после каждого раздумья в лог
  (`journalctl`) пишется строка `расход раздумья <NPC>: N промпт (K кэш) / M ответ; за раунд ≈ $X`.
  Контрольная сверка — дашборд провайдера (platform.openai.com/usage / openrouter.ai/activity).
- **Потолок**: `llm_npc_budget_usd` > 0 — при достижении каждый NPC один раз говорит
  «наговорились — голова гудит» и молчит до конца раунда (`BudgetExcused`). Консолидация
  памяти тоже учитывается (строка «консолидация <файл>»).
- **Пер-NPC модель/ключ**: в прототипе LlmNpc — `modelOverride`, `endpointOverride`,
  `apiKeyCvar` (ИМЯ cvar'а, не сам ключ — репозиторий публичный!). Так Ева может говорить
  на claude-haiku, а Макс на gpt-5-mini; через OpenRouter обе модели идут по одному ключу.

Модели: нужен tool-calling. Проверено: gpt-4o(-mini), gpt-4.1, gpt-5-mini (reasoning-ветка:
без temperature, `max_completion_tokens`, `reasoning_effort=low` — определяется по префиксу
`gpt-5`/`o1`/`o3`/`o4`). RP без цензуры — OpenRouter (deepseek-chat с инструментами; magnum/euryale
без). Цены/выбор — см. историю: gpt-5-mini лучший баланс.

## Ключевые решения и грабли (не наступать повторно)

- **Стиринг без HTN**: `EnsureComp<ActiveNPCComponent>` + `NPCSteeringSystem.Register` (паттерн
  ArrestBotSystem). ГРАБЛИ: (1) Register по живой компоненте НЕ сбрасывает `Status` — после
  первого прибытия он вечно `InRange`, и NPC больше никогда не двигается: всегда ставить
  `Status = Moving` (см. `RegisterSteering`); (2) `GetFlags(uid)` требует NPC-мозг и для нас
  возвращает None — двери непроходимы: ставим `PathFlags.Interact|Access`; (3) перерегистрация
  каждый тик за движущейся целью отменяет недостроенный путь — троттлить (порог 1.5 тайла,
  `RepathIfTargetMoved`); (4) гость за барной стойкой недостижим вплотную (NoPath) — вручать
  через стойку с 2.6 тайла при NoPath/InRange.
- **Слух**: EntitySpokeEvent — только речь; для эмоутов и объявлений добавлены свои события
  (помеченные вставки Corvax-Wega в ChatSystem.PrivateAPI/Announcements). Фильтры: только
  MobState (вендоматы кричат рекламу тем же каналом!), прямая видимость (не сквозь стены),
  не слушать других LLM-NPC (зациклятся).
- **Свои действия — в контекст** (`NoteOwnAction`): свои эмоуты NPC не слышит, и без заметок
  модель считала заказ невыполненным («спасибо» → делала второй коктейль).
- **Ингредиенты — три источника**: раздатчики (сливаем из бутылей), вендинг-автоматы
  (АлкоМат = VendingMachineBooze, НЕ ReagentDispenser! счётчик бутылок реально уменьшается),
  принесённые предметы рядом/в руках (яйцо = Solution с реагентом Egg; предмет расходуется).
  Реакция в стакане идёт настоящей химией (TryAddReagent → UpdateChemicals); Shake/Stir-рецепты —
  фолбэк готовым продуктом после честного расхода сырья.
- **Мелкие модели** спамят инструментами: последний раунд tool-loop принудительно без
  инструментов + прямое требование ответить; защиты от дублей make_drink/give_item;
  во время готовки другие поручения тела блокируются (go_to обрывал GoMix — коктейль исчезал).
- **Акценты рас** (вульп «ррр») приходят уже искажёнными — промпт велит не комментировать.
- **Юникод от моделей** (неразрывные дефисы, умные кавычки) — нет в шрифте игры, чистится
  SanitizeText.
- **Живость**: облачко печати (TypingIndicator через Appearance), взгляд на ближайшего игрока
  (0.5с троттлинг), блуждание вокруг Home (10–35с, до 2 тайлов; во время разговора стоит;
  якорь Home двигают только команды — stop/«стой тут», walk, go_to), поворот к говорящему/при вручении, снятие
  SSDIndicator/MindExaminable (иначе «Zz» и «в КРС»), проактивные приветствия (кулдаун 5 мин)
  и разбитие тишины (90с тишины, кулдаун 4 мин), станционные объявления в контекст.
- **Память**: `- [stamp] факт` построчно, дедуп по вхождению; при 40+ строках фоновая
  консолидация той же моделью в досье (CompleteTextAsync). Гигиена на обоих концах: remember
  в промпте требует только ДОЛГОВРЕМЕННЫЕ факты («пригодится ли через неделю?», чаще пустая
  строка), консолидация выбрасывает сиюминутное/сцены/интим, пишет «Мои заметки» от первого
  лица, досье о самой Еве не заводит, лимит 60 строк. Совсем мусор чистить руками в
  `data/llm_npc/bartender.md`. В промпт уходит НЕ весь файл: `FilterMemory` берёт только
  досье людей, которые сейчас рядом/в диалоге, общие секции («Мои…», «Событ…») и свежие
  `[stamp]`-строки; память < 1200 симв. не фильтруется.
- **Настроение и отношения**: `Mood` (свободный текст в промпт, ставится кодом при боли и самой
  моделью через set_mood; затухает по MoodUntil — обиды не вечны, извинение снимает раньше)
  и `Attitude` (имя → «тепло/холодно…», инструмент set_attitude; видна в осмотре рядом с именем).
  Долговременное — по-прежнему только через remember/память.
- **Не встревает**: реплика, начинающаяся с имени ДРУГОГО человека рядом («Лия, пойдём»), пишется
  в контекст, но ответ не взводит (`AddressedToAnother`); чужие эмоуты без её имени триггерят
  ответ лишь в ~35% случаев. Упоминание её имени — всегда приглашение.
- **Внешность людей**: флейвор-текст осмотра (DetailExaminable.Content) для людей ≤ 5 тайлов идёт
  в осмотр (обрезка 160 симв.) — может комментировать вид гостя; промпт велит не зацикливаться.
  Там же — что у гостя в руках (до 2 предметов, ≤ 5 тайлов): топор и букет — разные поводы.
- **Присутствие гостей** (`UpdatePresence`, скан 5с): заметки «Иван ушёл» (если пробыл ≥ 45с и
  пропал из зоны ≥ 12с) и «Иван вернулся после отлучки ~N мин» (отлучка > 3 мин) идут в контекст —
  иначе для модели диалог продолжался, будто гость никуда не отходил. Только игроки (Actor).
- **Чаевые** (`UpdateTips`): пачка кредитов (CashComponent+Stack) вне контейнера ≤ 3 тайлов —
  разовая заметка (дедуп по NotedTips) с суммой и ближайшим к деньгам игроком как дарителем +
  быстрый ответ-благодарность; подобрать может сама (pick_up), щедрость — в attitude/память.
- **Происшествия** (`OnThrown` — ThrownEvent broadcast; `UpdateLooseItems` в скане): броски
  предметов (заметка + реплика с шансом 40%, троттлинг 8с), разбитое стекло (появился `Shard*`
  ≤ 6 тайлов — «звон», дедуп NotedShards), кражи: у бесхозной вещи запоминается вероятный
  владелец (игрок ≤ 2 тайла при появлении, или швырнувший); если вещь оказалась в инвентаре
  ДРУГОГО (цепочка контейнеров до моба, `FindRootMob`) — «взял ЧУЖОЕ». Промпт: в руках у
  гостей — фон (один раз и только примечательное), на происшествия реагировать по ситуации.
- **Лукавство**: промпт разрешает хитрить/приукрашивать в характере, но честно отвечать на
  прямые фактические вопросы (память, рецепты, что видела).
- **Объявления станции**: пишутся в контекст всем NPC; если рядом есть игрок (и не мьют) —
  она сама комментирует новость через пару секунд.
- **Тренер арены «Макс»** (`MobLlmTrainer`, тот же yml-файл): второй LLM-NPC — мужчина
  (`sex: Male` у LlmNpc), ветеран в боевой форме (тактическая водолазка/разгрузка/берцы,
  КПК в руке), разбирает бои. Инструмент `fight_stats(person, scope)` тянет отчёт из
  `ArenaFightLogSystem` (Content.Server/_Wega/Duel/): урон нанесён/получен по типам, точность
  мили по оружию (замахи/попадания), стрельба (выстрелы/попадания), противники, исход.
  scope=last (дефолт) — только последняя ДУЭЛЬ; scope=all — вся сессия (только если прямо
  попросили). ФИЛЬТР ШУМА: урон от окружения (разгерма/атмос/падение — Origin не моб) бой НЕ
  заводит (только фоном в уже идущий); удар/выстрел в воздух вне боя эпизод не рождает
  (StartEp только на PvP-контакт, иначе CurrentEp). Эпизод метится `IsDuel`, если игрок на
  гриде арены (DuelArenaComponent.GridUid); в отчёт идут только `IsMeaningful` (дуэль ИЛИ
  противник + обмен ≥20 ИЛИ победа/поражение) — «зашёл в разгерму на 2 урона» отсекается.
  Скудные бои помечаются `[данных мало]`, промпт Макса велит тогда не выдумывать разбор.
  Каждая дуэль получает СКВОЗНОЙ НОМЕР за раунд (счётчик в DuelArenaSystem →
  DuelArenaComponent.DuelNumber): звучит в объявлениях старта/финала («Дуэль №7 началась!»),
  в летописи (FightEpisode.DuelNumber), в голосе Феликса/разборе Макса и в распечатке
  («дуэль №7 на арене»). ГРАБЛИ: летопись ключуется по **NetUserId** (ActorComponent.PlayerSession), НЕ по EntityUid —
  после смерти в дуэли игрок может получить новое тело, и статистика по старому uid терялась
  («Записей нет» сразу после честной дуэли, при этом уличные тычки находились).
  ПЕЧАТЬ (`PrintFightReport`): вместе с ответом анализатор спавнит бумагу «распечатка боя: N»
  с полным отчётом (PaperSystem.SetContent, [head]-разметка) — Макс берёт её во вторую руку
  (в первой анализатор) и вручает запросившему (параметр recipient инструмента; GiveItem-
  поручение). Руки заняты — лист остаётся лежать; печать только у NPC с GadgetProto.
- **Анализатор — используемый предмет** (`FightAnalyzerComponent`/`FightAnalyzerSystem` в Duel/,
  клиент `FightAnalyzerWindow`): активация HandheldFightComputer в руке открывает UI — слева
  «Сводка сессии» + список всех дуэлей раунда (номер, участники, давность), справа отчёт с
  бар-чартами (та же разметка, что на бумаге; дуэле-центричные отчёты `ListDuelReports`/
  `GetDuelReport`/`GetSessionOverview` собираются из эпизодов ВСЕХ игроков по DuelNumber),
  кнопка «Распечатать» — бумага в руки (кулдаун 3с). Работает у любого, кто держит анализатор
  (украсть у Макса = получить доступ к архиву — фича).
- **Феликс — версия БЕЗ LLM** (`MobArenaStatClerk`, `ArenaStatClerkSystem` в Duel/): «вендомат
  статистики» — клик рукой → стук по анализатору (тот же звук) → через 2.5с распечатка ТВОЕЙ
  последней дуэли в руки + дежурная фраза; дуэлей нет — отшивает. Кулдаун 8с на игрока, ноль
  запросов к API. Образ: котелок, костюм юриста, очки, белые перчатки, анализатор в руке.
  Ставить, где LLM выключен или жалко токенов; Макс — для разговора, Феликс — для конвейера. Антураж (`GadgetProto`/`TakeOutGadget`/`StowGadget`): в кожаной сумке лежит
  настоящий предмет `HandheldFightComputer` («портативный боевой анализатор», спрайт ручного
  крю-монитора); при fight_stats он РЕАЛЬНО достаётся в руку + звук печати
  (`Audio/_Wega/Effects/keyboard_typing.ogg`, МОНО — позиционный; из '400 Sounds Pack', itch.io,
  см. attributions.yml), а через 2.5с после выдачи ответа (или ошибки API) убирается обратно
  в сумку (SharedStorageSystem.Insert; не влез — остаётся в руке). Гаджет украли — фолбэк-эмоут
  без предмета. Спрайт анализатора — `_Wega/Objects/Specific/fight_analyzer.rsi`, генерится
  `dev/gen_fight_analyzer.py` (корпус/экран рисуются, геометрия хвата перекрашена из
  handheldcrewmonitor.rsi) — PNG руками не править, менять генератор. Бои режутся на эпизоды по паузе 25с/смерти,
  хранится 5 последних на игрока, in-memory на раунд. ГРАБЛИ: движок разрешает ОДНУ
  directed-подписку на пару (компонент, событие) глобально — (MobState, MobStateChanged)
  занята SharedStunSystem (слушаем broadcast), (Projectile, ProjectileHit) занята
  SharedProjectileSystem (подписка через TransformComponent). memoryFile=trainer —
  своя память, с Евой не пересекается.

```bash
cd /opt/wega/server && git pull

# Debug и Release собираются в ОДНУ папку, сервис (--no-build) запускает последний собранный!
```

Конфиг: `/opt/wega/server/server_config.toml` (untracked, переживает git reset). Секция `[wega]`
строго одна. Ключ — только там, никогда в git/чат; засветился — перевыпустить.

но не clean). Память локально: `bin/Content.Server/data/llm_npc/`.

## Диагностика (sawmill `llm_npc`)

`думает: модель X` → запрос ушёл; `инструмент N(args) → результат` → tool-calling;
`проверка запасов «X»: ... реагент Y: нужно N, есть M` → почему отказ; `вычерпано/открыта
бутылка/использован предмет` → расход; `финальный раунд: инструменты отключены` → анти-спам;
`ответ: say=...` → успех; `HTTP-запрос упал (попытка k/3)` → сеть (есть 3 ретрая);
`память консолидирована` → сжатие памяти.

- Brave Search вместо DuckDuckGo (новости).
- Лор станции файлом в промпт.
- Реакция на касания кликом (InteractionSuccessEvent) + запрет раздевания (RemComp Strippable).
- Персона из логов игрока: каркас есть (LlmPersona/LlmNpcSystem.Persona, команда llm_persona) —
  дистилляция стиля из сырых логов в `data/llm_npc/persona_*.md`.
- Движковый фикс скролла ItemList (медиаплеер) живёт НЕЗАКОММИЧЕННЫМ в сабмодуле RobustToolbox —
  клиентские сборки для игроков собирать с этой машины, иначе фикс потеряется.
