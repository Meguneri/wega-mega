# Повторяемое развёртывание Wega Mega

Набор для чистого VPS: Ubuntu 24.04 x86-64, systemd, SSH-доступ root по ключу.
Адреса серверов, ключи и базы в Git не сохраняются. Индивидуальные сведения о
действующем VPS — в игнорируемом `DEPLOY.md` в корне проекта.

## Развёртывание из Git с сохранёнными настройками

Подготовленный приватный набор хранится в `.cache/deployment`: актуальные
`server_config.toml`, `preferences.live.db`, `deploy.env` и контрольные суммы
`manifest.json`. Снимок базы сделан 2 октября 2026 без остановки игры.
Каталог игнорируется Git; при переносе самого набора на другой компьютер
сохраните его отдельно вместе с `dev/vps` и скриптом подготовки базы.

```powershell
.\dev\vps\deploy-from-git.ps1 -Vps NEW_VPS_IP -SshKey C:\path\to\ssh_key
```

Команда предназначена для чистого Ubuntu 24.04 x86-64. Она переносит настройки,
персонажей и права, устанавливает зависимости и .NET, скачивает выбранную ветку
`codex/upstream-integration` с GitHub и собирает Server/Client на новом VPS.
Готовые бинарники не копируются. После первого запуска обновления собираются
автоматически и применяются только при следующем запуске игрового процесса.
Обновляющий скрипт сам не останавливает и не перезапускает игру.
Первое развёртывание стартует игру автоматически после успешной сборки.
Для порта 1212 нужны TCP и UDP в firewall провайдера.

## Быстрый перенос готовой сборки

Один раз экспортировать готовую Linux-сборку с действующего VPS:

```powershell
.\dev\vps\cache-bundle.ps1 -Vps OLD_VPS_IP -SshKey C:\path\to\ssh_key
```

Архив, SHA-256 и номер коммита сохраняются в игнорируемом `dev/vps/.cache`.
Экспорт не останавливает сервер и не включает базу, конфигурацию и журналы.
Полученный архив нельзя выкладывать в Git; он нужен как локальный кэш.

Затем развернуть на новом VPS из корня проекта:

```powershell
.\dev\vps\deploy.ps1 -Vps NEW_VPS_IP -SshKey C:\path\to\ssh_key -BundleDirectory .\dev\vps\.cache
```

Архив закреплён за конкретным коммитом: новая установка запускается ровно на
этой работающей сборке даже тогда, когда ветка Git уже ушла вперёд. Компиляция
пропускается. Позднейшие коммиты автоматически собираются отдельно. Готовая версия применяется
при следующем запуске службы; обновляющий скрипт игру не останавливает.
Это не Windows-сборка: экспортируется работающая Linux-сборка с VPS.

## Без кэша

```powershell
.\dev\vps\deploy.ps1 -Vps NEW_VPS_IP -SshKey C:\path\to\ssh_key
```

По умолчанию: ветка `codex/upstream-integration`, база
`bin/Content.Server/data/preferences.db`, полные игровые права для Meguneri и
arhont1234. Параметры `-Branch`, `-Database`, `-Admins` и `-ServerConfig` позволяют
выбрать другие значения. Пользовательская конфигурация должна сохранять
`auth.mode=1`, `auth.allowlocal=false` и порт 1212.
Для точного клона действующего сервера укажите
`-Database .\dev\vps\.cache\preferences.live.db`; файл содержит персонажей и
должен храниться только локально, отдельно от Git.

Установлены Python со стандартным sqlite3 и OpenSSH-клиент на компьютере запуска.
Серверная часть устанавливает .NET 10 и зависимости сама. Источник Git публичный:
`https://github.com/Meguneri/wega-mega.git`; ключи доступа к Git не нужны.

## Что происходит

1. Создаётся согласованная SQLite-копия, включая активный WAL; исходная база не меняется.
2. Владельцы персонажей сверяются с публичными идентификаторами аккаунтов SS14.
   Несовпадение офлайн-ID с реальным аккаунтом останавливает перенос и требует
   отдельной миграции; чужие персонажи автоматически не присваиваются.
3. Только указанным администраторам выдаются все актуальные флаги из AdminFlags.cs.
4. На чистом VPS устанавливаются зависимости, непривилегированный пользователь
   wega и 4 ГБ swap, если подкачки ещё нет. Существующая установка не перезаписывается.
5. Загружается готовый архив либо собираются Server и Client в Release при первом развёртывании.
6. База и настройки размещаются вне каталога сборки; включаются службы.

## Обслуживание

- `wega.service`: запуск при загрузке ОС, перезапуск процесса через 5 секунд.
- `wega-update.timer`: проверка выбранной ветки и фоновая сборка каждые 10 минут без перезапуска игры.
- `/etc/wega/deploy.env`: выбранная ветка для дальнейших обновлений.
- `/usr/local/sbin/wega-update`: Git fetch и подготовка Server/Client для следующего запуска службы.
- `/usr/local/sbin/wega-install-release`: ручная установка с проверкой отсутствия игроков,
  резервной копией базы и откатом при неготовности новой версии.
- `/usr/local/sbin/wega-apply-pending`: применение готовой версии перед запуском процесса с резервной копией базы.
- `/opt/wega/pending`: готовая версия для следующего запуска.
- `/var/lib/wega/data`: база; `/var/lib/wega/backups`: резервные копии.
- `/opt/wega/current`: текущая версия; `/opt/wega/releases`: сохранённые версии.

Резервные копии и версии автоматически не удаляются: следить за свободным местом.
Автопроверка не перезапускает игру. При ошибке ручной сборки текущая версия продолжает работать. При ошибке старта после
переключения возвращаются предыдущие сборка и база; неудачная база сохраняется.
Действующий VPS не изменяется простым редактированием этих локальных шаблонов.

## Проверка результата

Команда deploy запускает установку в фоне, а не подтверждает её завершение.
Перед подключением проверить:

```bash
journalctl -u wega-initial-deploy -n 30 --no-pager
systemctl status wega
systemctl is-enabled wega wega-update.timer
curl --fail http://127.0.0.1:1212/info
```

Нужны сообщение `Server Version ... -> Ready`, ответ `/info` с `Required` и
успешный GET `/manifest.txt` извне. Не использовать HEAD для проверки манифеста:
в этой версии движка обработчик может записывать тело и после закрытия HEAD-запроса.
Открыть TCP и UDP 1212 в панели провайдера, если там есть внешний firewall.
Адрес лаунчера: `ss14://NEW_VPS_IP:1212`; проверить вход и персонажей обоих аккаунтов.
В `wega.allowed_account_ids` разрешены только подтверждённые ID Meguneri и
arhont1234; административные права не дают обхода этого списка.
`wega.disable_humanoid_satiation` убирает голод и жажду у гуманоидов, включая
уже созданных. `shuttle.auto_call_time = 0`, `viewport.maximum_width = 29` и
`events.enabled = false` сохранены в конфигурации и применяются после ручного
перезапуска игры.

## Проверки набора без VPS

```powershell
python -m unittest discover -s dev/vps -p 'test_*.py' -v
```

Тесты проверяют согласованный перенос WAL, выдачу прав только в копии, отказ от
перезаписи существующего файла и отказ от несовпадающего идентификатора аккаунта.

Автосборка не вызывает stop/restart службы даже при отсутствии игроков. Перезапуск
раунда не применяет обновление: нужен новый запуск процесса сервера. При аварийном
завершении штатный Restart=always также запускает подготовленную версию.
